## 1. Цель работы

Самостоятельно собрать матричный reverse-mode autograd и обучить
многослойный перцептрон для классификации трёх сортов вина по 13 числовым
признакам. В конце notebook (и проекта) должно быть показано:

* корректные градиенты всех матричных операций;
* совпадение autograd с центральной разностью;
* работу моделей без скрытых слоёв, с одним и с несколькими скрытыми слоями;
* обучение архитектуры **13 → 16 → 8 → 3** методом mini-batch SGD;
* train accuracy = 1.0, validation accuracy ≥ 0.95, test accuracy ≥ 0.95;
* воспроизводимый inference после сохранения/загрузки.

## 4. Ключевые формулы (из theory.pdf)

**Forward** (для скрытого слоя ℓ):

* `H̃⁽ℓ⁻¹⁾ = [1_B | H⁽ℓ⁻¹⁾]`
* `R⁽ℓ⁾ = H̃⁽ℓ⁻¹⁾ (W⁽ℓ⁾)ᵀ`
* `H⁽ℓ⁾ = φ⁽ℓ⁾(R⁽ℓ⁾)`
* `Z = H̃⁽ᴷ⁻¹⁾ (W⁽ᴷ⁾)ᵀ`
* `P = softmax(Z)`
* `L_B = −(1/B) Σ_μ Σ_κ y_μκ log p_μκ`

**Backward**:

* `G_Z = (P − Y) / B`
* `∇_{W⁽ℓ⁾} L_B = (G_{R⁽ℓ⁾})ᵀ H̃⁽ℓ⁻¹⁾`
* `G_{H⁽ℓ⁻¹⁾} = G_{R⁽ℓ⁾} W⁽ℓ⁾_{:,1:}`
* `G_{R⁽ℓ⁻¹⁾} = G_{H⁽ℓ⁻¹⁾} ⊙ φ⁽ℓ⁻¹⁾'(R⁽ℓ⁻¹⁾)`

**Маршрут обратного прохода**:

```
L_B → G_Z → ∇W⁽²⁾ и G_{H⁽¹⁾} → G_{R⁽¹⁾} → ∇W⁽¹⁾ и G_{H⁽⁰⁾}
    → G_{R⁽⁰⁾} → ∇W⁽⁰⁾ → G_X
```

## 5. Проверки, которые проходит код

1. **Устойчивый softmax** — не переполняется при |logit| = 1000.
2. **Контракт MatrixValue** — скалярная потеря принимает seed = 1
   неявно, матрица (1, 1) требует явный seed.
3. **Транспонирование** — форма градиента родителя возвращается.
4. **Матричное произведение** — оба VJP проверены численно; при общем
   родителе оба вклада суммируются через `+=`.
5. **augment_with_ones** — первый столбец градиента отбрасывается.
6. **ReLU/tanh** — производные в точке 0 и через `1 − tanh²`.
7. **Fused softmax–CCE** — градиент `(P − Y)/B`, сумма по строке = 0.
8. **Центральная разность** — аналитический и численный градиенты
   совпадают с `rel_tol = 1e-6`.
9. **Формы MLP** — K = 0, 1, 2 и один объект `(1, d)`.
10. **Итератор mini-batch** — последний неполный batch (13 объектов)
    сохраняется.
11. **End-to-end gradient check** — один элемент первой матрицы весов
    сверяется с центральной разностью всей сети.
12. **После обучения** — loss убывает, best_epoch согласован с минимумом
    val_loss, восстановление из памяти и из файла совпадает.
13. **Evaluation** — все критерии Business Understanding выполнены,
    confusion matrix 3 × 3, сумма 26.
14. **Inference** — вероятности загруженной модели совпадают с исходной.

## 7. Ответы на вопросы самопроверки

1. **Почему `result.grad` в `__matmul__` — это VJP-вход, а не якобиан?**
   Якобиан — полная таблица ∂M_ik/∂A_pq; callback использует только
   свёртку `Jᵀ · G_M` с уже известным G_M, то есть одно действие
   якобиана на вектор. Полный якобиан не материализуется.

2. **Откуда в ∇W·L сумма по строкам batch?**
   Один и тот же вес w_sj используется для всех B объектов. Полная
   производная — это сумма путей через каждый объект:
   ∂L/∂w_sj = Σ_μ g_{r_μs} · h̃_μj.

3. **Почему `augment_with_ones` удаляет первый столбец градиента?**
   Первый столбец H̃ — константа 1, у неё нет родителя, значит
   соответствующая компонента градиента не передаётся дальше.

4. **Почему fused softmax–CCE даёт (P − Y)/B?**
   Правило цепочки для суммы по всем классам строки сокращает якобиан
   softmax до `p_ic − y_ic`, а множитель 1/B — от среднего по batch.

5. **Чем различаются B = 1, 1 < B < n и B = n?**
   B = 1 — SGD, шумный градиент, n обновлений; 1 < B < n — mini-batch
   SGD; B = n — full-batch GD, один точный градиент на эпоху.

6. **Почему validation и test нельзя включать в mean/std?**
   Это утечка информации: статистики train должны быть независимы от
   данных, на которых модель проверяется, иначе оценка обобщения
   завышена.

7. **Какие величины нужны для воспроизводимого inference?**
   Архитектура, активации, все матрицы весов, train-средние и train-std,
   порядок признаков, исходные метки классов, версия формата.
